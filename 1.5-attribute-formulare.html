Lektion 1.5 — Teil 1: Web & HTML

Attribute & Formulare

HTML ca. 90 min Grundlagen

Lernziele

  • Wissen, was HTML-Attribute sind, und die wichtigsten Attribute kennen
  • Boolean-Attribute wie required, disabled, checked verwenden
  • Ein Formular mit <form>, <label>, <input> und <button> aufbauen
  • Den Unterschied zwischen id, for und name erklären
  • Verschiedene Input-Typen sowie <textarea> und <select> einsetzen
  • Daten mit action und method (GET/POST) senden und eingebaute HTML-Validierung nutzen

1 — HTML-Attribute

Attribute liefern zusätzliche Informationen zu einem HTML-Element oder verändern sein Verhalten. Sie stehen immer im öffnenden Tag:

Syntax HTML 
<element attribut="wert">

Beispiele:

Beispiele HTML 
<a href="https://www.example.com">Link</a>
<img src="bild.jpg" alt="Beschreibung des Bildes">
<input type="text" name="vorname">

Boolean-Attribute

Manche Attribute brauchen keinen Wert: Ihre bloße Anwesenheit schaltet die Eigenschaft ein. Fehlt das Attribut, ist sie aus.

Boolean-Attribute HTML 
<input required>
<input disabled>
<input checked>
⚠
Achtung bei Boolean-Attributen
disabled="false" schaltet das Feld trotzdem ab – denn das Attribut ist vorhanden. Um es zu deaktivieren, muss man das Attribut ganz weglassen.

3 — HTML-Formulare

Benutzereingaben werden über Formulare erfasst:

Formular HTML 
<form> ... </form>

Das einfachste Formular:

Einfachstes Formular HTML 
<form>
  <label for="vorname">Vorname:</label>
  <input type="text" id="vorname" name="vorname">
  <button type="submit">Absenden</button>
</form>

4 — Rollen von form, label, input, button

ElementRolle
<form>fasst Eingabefelder zusammen
<label>beschreibt ein Eingabefeld
<input>nimmt Eingaben entgegen
<button>löst eine Aktion aus

Drei Attribute werden gerne verwechselt:

AttributAufgabe
ididentifiziert ein konkretes Element (eindeutig auf der Seite)
forverbindet ein <label> mit dieser id
nameSchlüssel, unter dem der Wert an den Server übertragen wird
id, for und name HTML 
<label for="email">E-Mail</label>
<input id="email" name="kontakt_email">

Hier verbindet for="email" das Label mit dem Feld id="email" – ein Klick auf „E-Mail“ setzt den Cursor ins Feld, und Screenreader lesen das Label vor. Beim Absenden wird der Wert aber unter dem Namen kontakt_email übertragen, z. B. ?kontakt_email=max@example.com.

5 — Input-Typen

Dasselbe Element <input> bekommt über das Attribut type verschiedene Funktionen:

Input-Typen HTML 
<input type="text">
<input type="email">
<input type="password">
<input type="number">
<input type="date">
<input type="checkbox">
<input type="radio">
Live-Vorschau
text email password number date checkbox vegetarisch radio leicht schwer
💡
Der richtige Typ hilft mobil

Auf dem Smartphone zeigt type="email" eine Tastatur mit @, type="number" eine Zifferntastatur und type="date" einen Kalender. Außerdem prüft der Browser das Format automatisch.

6 — Weitere Formularelemente

textarea, select, button HTML 
<textarea name="nachricht"></textarea>

<select name="land">
  <option value="at">Österreich</option>
  <option value="de">Deutschland</option>
  <option value="ch">Schweiz</option>
</select>

<button type="submit">Absenden</button>
<button type="reset">Zurücksetzen</button>
  • <textarea> – mehrzeiliges Textfeld
  • <select> mit <option> – Auswahlliste; übertragen wird das value der gewählten Option (z. B. land=at)
  • <button type="submit"> sendet das Formular ab, <button type="reset"> setzt alle Felder zurück

7 — Daten senden: action, method + HTML-Validierung

actionWohin werden die Daten geschickt?
methodWie werden die Daten übertragen?
GETDaten werden Teil der URL (Query-String)
POSTDaten werden im Request-Body übertragen (nicht in der URL sichtbar)
Suche mit GET HTML 
<form action="/suche" method="get">
  <input name="q">
  <button type="submit">Suchen</button>
</form>

Beispiel-Ergebnis nach Eingabe von „html“: /suche?q=html

Eingebaute Validierung ohne JavaScript

HTML-Validierung HTML 
<input type="email" name="email" required>
<input name="benutzername" required minlength="3" maxlength="20">

Nützliche Attribute: required, minlength, maxlength, min, max, pattern

Live-Vorschau: auf „Prüfen“ klicken, ohne etwas einzugeben
⚠
Validierung im Browser ersetzt keine Prüfung am Server

Die HTML-Validierung verbessert die Bedienbarkeit, lässt sich aber leicht umgehen (z. B. über die Entwicklertools). Ein Server muss empfangene Daten immer selbst noch einmal prüfen.

Projektschritt

Projektschritt 1.5

Newsletter-Formular

Im <footer> ergänzen wir ein Formular zur Newsletter-Anmeldung mit HTML-Validierung:

demoseite/index.html (footer) HTML 
<section class="newsletter">
  <h2>Newsletter</h2>
  <form class="newsletter-form" action="/newsletter" method="post">
    <label for="name">Name</label>
    <input type="text" id="name" name="name" placeholder="Ihr Name" required>

    <label for="email">E-Mail</label>
    <input type="email" id="email" name="email" placeholder="ihre.email@example.com" required>

    <label>
      <input type="checkbox" name="kein-roboter" required>
      Ich bin kein Roboter
    </label>

    <button type="submit">Jetzt anmelden</button>
  </form>
</section>

Sende das Formular leer ab: Der Browser verhindert das Absenden und markiert das erste Pflichtfeld. Mit gültigen Daten kommt ein 404-Fehler – erwartet, denn es gibt noch keinen Server unter /newsletter.

📁 Fertiger Stand am Ende von Teil 1: beispiele/1.5/

Häufige Fehler

Fehler: name-Attribut vergessen

Das Feld wird angezeigt, beim Absenden fehlt der Wert aber komplett.

Nur Felder mit name werden übertragen. Jedes Eingabefeld braucht ein name-Attribut.

Fehler: for und id passen nicht zusammen

<label for="mail"> und <input id="email"> – das Label ist mit keinem Feld verknüpft.

Der Wert von for muss exakt der id des Feldes entsprechen.

Fehler: Passwörter mit GET senden

Bei method="get" landen alle Daten in der URL – und damit im Verlauf und in Server-Logs.

Für sensible Daten und Daten, die etwas verändern (Anmelden, Newsletter abonnieren), method="post" verwenden.

Aufgaben

Aufgabe 1 Schwierigkeitsgrad per Radio-Buttons

Ergänze das Einreichen-Formular um drei Radio-Buttons „leicht“, „mittel“, „schwer“. Achte darauf, dass alle drei denselben name haben – warum ist das nötig?

Aufgabe 2 Bild-Upload

Recherchiere den Input-Typ file und das Attribut accept. Füge ein Feld hinzu, das nur Bilder (image/*) akzeptiert.

Aufgabe 3 GET vs. POST beobachten

Ändere die Methode des Einreichen-Formulars testweise auf get und sende es ab. Wie sieht die URL aus? Ändere sie danach wieder auf post und schau im Tab Network der Entwicklertools nach, wo die Daten nun stehen.

Bonus pattern für Postleitzahlen

Füge ein Feld für eine österreichische Postleitzahl hinzu, das mit dem Attribut pattern genau vier Ziffern erzwingt.
