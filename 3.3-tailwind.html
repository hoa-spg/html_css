Lektion 3.3 — Teil 3: CSS-Frameworks

Tailwind CSS

Tailwind CSS ca. 90 min Framework

Lernziele

  • Den Utility-First-Ansatz von Tailwind vom Komponenten-Ansatz von Bootstrap unterscheiden
  • Tailwind für Experimente über das CDN-Script einbinden
  • Die wichtigsten Utility-Klassen für Abstände, Farben, Typografie, Flexbox und Grid lesen und schreiben
  • Responsive Varianten (md:, lg:) und Zustands-Varianten (hover:, focus:, dark:) einsetzen
  • Entscheiden, wann eigenes CSS, Bootstrap oder Tailwind sinnvoll ist

1 — Was ist Tailwind CSS?

Tailwind CSS ist ein CSS-Framework, das – anders als Bootstrap – keine fertigen Komponenten wie Cards oder Navbars mitbringt. Stattdessen liefert es sehr viele kleine Utility-Klassen, die jeweils genau eine CSS-Eigenschaft setzen. Das Aussehen entsteht, indem man diese Klassen direkt im HTML kombiniert.

BootstrapTailwind CSS
AnsatzKomponenten (card, btn, navbar)Utility-First (p-6, rounded, bg-white)
AussehenEinheitlicher „Bootstrap-Look“Kein Standard-Look, alles individuell
JavaScriptEigene JS-Komponenten (Modal, Dropdown …)Keines – Interaktion selbst programmieren
HTMLWenige, sprechende KlassenViele kurze Klassen pro Element
EinsatzSchnelle Prototypen, Admin-OberflächenIndividuelle Designs, Komponenten-Frameworks (React, Vue, Angular)

Dieselbe Karte in beiden Frameworks:

Bootstrap HTML 
<div class="card h-100 shadow-sm">
  <div class="card-body">
    <h2 class="h5 card-title">Karte 1</h2>
    <p class="card-text">Bootstrap liefert viele vorgefertigte Komponenten und sinnvolle Standardabstände.</p>
    <a href="#formular" class="btn btn-primary">Zum Formular</a>
  </div>
</div>
Tailwind HTML 
<div class="h-full rounded-lg bg-white p-6 shadow-sm">
  <h2 class="text-xl font-semibold">Karte 1</h2>
  <p class="mt-3 text-slate-600">Tailwind arbeitet mit Utility-Klassen, die direkt Aussehen und Abstände definieren.</p>
  <a href="#formular" class="mt-4 inline-block rounded bg-blue-600 px-4 py-2 text-white hover:bg-blue-700">Zum Formular</a>
</div>
💡
Utilities sind nur CSS

Jede Tailwind-Klasse entspricht einer bekannten CSS-Deklaration: p-6 ist padding: 1.5rem, rounded-lg ist border-radius: 0.5rem, flex ist display: flex. Wer CSS kann, kann Tailwind sehr schnell lesen.

2 — Setup

Für Experimente und kleine Seiten reicht ein Script-Tag im <head> (Tailwind 4, Browser-Build):

index.html (head) HTML 
<script src="https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4"></script>

Das Script durchsucht die Seite nach Tailwind-Klassen und erzeugt das passende CSS direkt im Browser.

⚠
Nur für Entwicklung

Der Browser-Build ist für Prototypen gedacht. In echten Projekten wird Tailwind über npm installiert und von einem Build-Tool (z. B. Vite) zu einer kleinen CSS-Datei kompiliert, die nur die tatsächlich verwendeten Klassen enthält (siehe JavaScript-Kurs, Lektion 1.1: Node.js und npm).

4 — Varianten: responsive und Zustände

Ein Präfix vor einer Klasse schränkt sie auf einen Breakpoint oder Zustand ein. Wie bei Bootstrap gilt Mobile First: Klassen ohne Präfix gelten immer, md: ab 768px aufwärts.

PräfixBedeutungEntspricht
sm: md: lg: xl:ab 640 / 768 / 1024 / 1280px@media (min-width: …)
hover:Maus über dem Element:hover
focus:Element hat den Fokus:focus
even:jedes zweite Element:nth-child(even)
dark:Betriebssystem im Dark Mode@media (prefers-color-scheme: dark)
Responsives Karten-Grid HTML 
<!-- mobil 1 Spalte, ab md 3 Spalten -->
<div class="grid gap-6 md:grid-cols-3">
  <div class="rounded-lg bg-white p-6 shadow-sm">…</div>
  <div class="rounded-lg bg-white p-6 shadow-sm">…</div>
  <div class="rounded-lg bg-white p-6 shadow-sm">…</div>
</div>
Formularfeld mit Fokus-Zustand HTML 
<label for="email" class="mb-2 block font-medium">E-Mail</label>
<input type="email" id="email" placeholder="name@beispiel.de"
       class="w-full rounded border border-slate-300 px-3 py-2 focus:border-blue-500 focus:outline-none">
Dark Mode HTML 
<body class="bg-slate-50 text-slate-800 dark:bg-slate-900 dark:text-slate-100">

5 — Eigenes CSS, Bootstrap oder Tailwind?

AnsatzStärkenSchwächen
Eigenes CSSVolle Kontrolle, kein Overhead, sauberes HTMLViel Arbeit, Konsistenz muss man selbst sicherstellen
BootstrapSehr schnell, fertige Komponenten inkl. JavaScriptSeiten sehen ähnlich aus, Anpassungen kämpfen gegen Vorgaben
TailwindIndividuelles Design ohne eigenes Stylesheet, konsistente SkalaLange Klassenlisten im HTML, Build-Schritt für Produktion
ℹ
Ausblick

In Komponenten-Frameworks wie React (2. Jahr) wird eine Karte nur einmal als Komponente geschrieben und dann wiederverwendet. Die langen Tailwind-Klassenlisten stehen dann nur noch an einer Stelle – deshalb ist Tailwind dort besonders beliebt.

Dokumentation: tailwindcss.com/docs

Häufige Fehler

Fehler: Bootstrap-Klassen in Tailwind (oder umgekehrt)

class="btn btn-primary" oder container row col-md-6 bewirken in Tailwind nichts bzw. etwas anderes.

Die beiden Frameworks haben unterschiedliche Klassennamen – nicht mischen, und immer in der Doku des verwendeten Frameworks nachschlagen.

Fehler: Responsive Präfix falsch herum gedacht

md:hidden wird als „auf Tablets verstecken“ verstanden.

Mobile First: md:hidden versteckt ab 768px aufwärts. „Nur mobil verstecken“ ist hidden md:block.

Fehler: Klassen dynamisch zusammengesetzt

"bg-" + farbe + "-600" in JavaScript erzeugt eine Klasse, die der Tailwind-Build nie im Quelltext gesehen hat – sie hat daher keine Styles.

Immer vollständige Klassennamen im Code schreiben (z. B. eine Zuordnung { rot: 'bg-red-600', blau: 'bg-blue-600' }).

Aufgaben

Aufgabe 1 Klassen übersetzen

Schreibe für jede Klasse die entsprechende CSS-Deklaration auf: mx-auto, max-w-6xl, py-12, rounded-full, items-center, lg:col-span-2, hover:-translate-y-1.

Aufgabe 2 Fehlende Bereiche ergänzen

Ergänze in index-tailwind.html die Abschnitte „Lernprojekt“ (nummerierte Liste mit list-decimal pl-6) und einen „Nach oben“-Link, der mit fixed bottom-6 right-6 rechts unten schwebt.

Aufgabe 3 Dark Mode

Ergänze dark:-Varianten für Hintergrund, Text und Karten, sodass die Seite im Dark Mode des Betriebssystems gut lesbar ist.
